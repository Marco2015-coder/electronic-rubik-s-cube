## 修复「打乱后方块重叠」（上次对话丢失后重新排查）

**根因 1（普通魔方，所有阶）**：`App.scramble()` 里 `puzzle.scramble()` 已经静默把整串打乱转到位了，随后 `viewport.requestMoves()` 又把同一串通过 `apply()` 执行第二遍；第二次执行时状态已变，旧的 `pieceIds` 不再是合法一层 → 块被打散。诊断数据：2 阶 4 对 / 3 阶 3 对 / 4 阶 23 对 / 5 阶 38 对重叠。

**修复**：
- `src/shared/puzzle/types.ts`：`Puzzle` 接口新增 `applySilent(move)`。
- `src/ui/viewport.ts`：`requestMoves` → 改为 `requestScramble(moves, duration)`，内部用 `applySilent` 入队。
- `src/ui/app.ts`：`scramble()` 改为 `scramble()` → `puzzle.reset()` → `requestScramble()`，从还原态重放，历史保持为空。

**根因 2（镜面魔方）**：三轴各用一套不同的随机切分，块转 90° 后跨度搬到别的轴上无法落格 → 单独调用也会重叠（3 阶 37 对 / 4 阶 123 对 / 5 阶 254 对）。

**修复**：`src/shared/puzzle/cubic.ts` 新增 `mirrorCutPositions()`，生成「关于 0 对称」的切分并三轴共用；`cutPositions()` 对 mirror 走它。同时 `isSolved()` 对镜面魔方的「正方体块」忽略朝向。

**回归测试**：`scripts/selftest.mjs` 新增 `aabb/countOverlap/poseKey` 辅助函数与检查——打乱后无块重叠、重放打乱序列复现同一状态且不污染历史、正方体块转 120° 仍判定归位。结果：157 项全通过；`npm run smoke` 未发现问题，`preview-out/` 截图确认普通三阶与镜面三阶打乱后都是严丝合缝的立方体。

**权衡说明**：镜面魔方因对称切分，块尺寸成对重复（不再两两不同），且打乱后外形仍保持立方体，不像真实镜面魔方那样凹凸。这是纯几何刚体模型下唯一能保证不重叠的做法（真实镜面魔方靠内部圆盘机构）。
